# PPC Boot Debug Status

## Boot Sequence

```
KPX interpreter (x86_64 host)
  → PPC nanokernel (ROM+0x310000) — boots hardware, sets up KernelData
    → PPC 68k emulator (ROM+0x460000) — interprets 68k Mac OS code
      → 68k Mac OS boot code (ROM+0x0000) — Toolbox, drivers, Finder
        → EMUL_OP traps (0xfe43+) → EmulOp C++ handlers
```

## Where Boot Diverges

EmulOps #1-#11 are **register-identical** to SheepShaver:

| # | Selector | 68k PC | Description |
|---|----------|--------|-------------|
| 1 | 1 (XPRAM1) | 0x50007a82 | NVRAM read — IDENTICAL |
| 2 | 1 (XPRAM1) | 0x50007a82 | NVRAM read — IDENTICAL |
| 3 | 1 (XPRAM1) | 0x50007a82 | NVRAM read — IDENTICAL |
| 4 | 7 (FIX_MEMTOP) | 0x5000012a | Fix MemTop — IDENTICAL |
| 5 | 39 (RESET) | 0x500011f6 | System reset — IDENTICAL |
| 6 | 2 (XPRAM2) | 0x50007f84 | NVRAM write — IDENTICAL |
| 7 | 2 (XPRAM2) | 0x50007f84 | NVRAM write — IDENTICAL |
| 8 | 1 (XPRAM1) | 0x50007a82 | NVRAM read — IDENTICAL |
| 9 | 1 (XPRAM1) | 0x50007a82 | NVRAM read — IDENTICAL |
| 10 | 8 (FIX_MEMSIZE) | 0x50000612 | Fix RAM size — IDENTICAL |
| 11 | 8 (FIX_MEMSIZE) | 0x50000612 | Fix RAM size — IDENTICAL |
| **12** | **SS: 4 (SONY_OPEN)** | **0x500538d6** | **DIVERGES HERE** |
| **12** | **MP: 48 (CHECKLOAD)** | **0x502fcf0a** | **Wrong code path** |

All PPC registers at EmulOp entry (r24, r29, r30, r31, r1, cr, xer) match through #11.
At #12, r29 (68k dispatch table pointer) differs by 0x160 — the 68k emulator decoded a different 68k opcode.

### Init Path (`src/core/cpu_context.cpp` init_ppc)

Sequence matches SheepShaver `main_unix.cpp`:
1. mmap RAM at address 0 (MAP_FIXED) — 64MB
2. mmap ROM at 0x50000000 (MAP_FIXED) — 5MB
3. Map KernelData at 0x68ffe000 + 0x5fffe000 via shmget (shared)
4. Map DR areas at 0x68070000, 0x69000000
5. Load ROM (4MB), copy to ROM area
6. SheepMem::Init() at 0x10000000
7. cpu_ppc_kpx_install() — creates sheepshaver_cpu
8. InitAll_PPC() — ThunksInit, PatchROM_PPC, KernelData, XLM
9. mprotect ROM read-only
10. cpu_init() — GPR3/GPR4/MODE_68K
11. Sync g_platform
12. Start tick thread (2s delay)

## Bugs Found and Fixed During Investigation

1. **XPRAM buffer overflow** — XPRAM_SIZE was 256 (m68k), PPC needs 8192. Code wrote past buffer.
2. **PPC_CHECK_INTERRUPTS=1** — Should be 0. Caused HandleInterrupt during 68k emulation.
3. **SheepRoutineDescriptor missing** — #if !EMULATED_PPC guards excluded routine descriptor creation.
4. **EmulOp stub shadowing** — cpu_ppc_kpx.cpp stubs for EmulOp, ThunksInit, NativeOpcode, InstallDrivers, CheckLoad, Execute68k all shadowed real implementations.
5. **CheckLoad signature mismatch** — uint8* vs uint16* for resource data pointer.
6. **KernelData2 unmapped** — 0x5fffe000 alternate KernelData not mapped.
7. **SheepMem in 64-bit space** — MAP_32BIT returned 64-bit address, truncated to 32 bits.
8. **Missing POWERPC_ROM define** — Affected XPRAM_SIZE and other conditionals.

## Remaining Mystery

The 68k Mac OS boot code takes a different path after FIX_MEMSIZE despite identical:
- Interpreter code (preprocessor verified)
- All RAM, ROM, KernelData, XLM, XPRAM memory
- EmulOp handler logic
- PPC register state at EmulOp boundary
- 32768-entry PPC flight recorder trace before EmulOp #1
- Zero SIGSEGVs, zero interrupts

**Hypothesis**: Something in the `0x18000-0x3fff00` RAM range (not yet dumped) differs, OR a difference in how the compile/link environment affects runtime behavior of the KPX decode cache.
